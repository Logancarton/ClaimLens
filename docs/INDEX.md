# ClaimLens Project Index

This folder is the project truth layer. Read documents in this order before major architecture or implementation work.

1. `PRODUCT_SCOPE.md` — what ClaimLens is and is not.
2. `USE_CASES.md` — concrete jobs the product must perform.
3. `PRODUCT_REQUIREMENTS.md` — functional and non-functional requirements.
4. `ARCHITECTURE.md` — canonical signal flow and ownership.
5. `DATA_MODEL.md` — objects and relationships ClaimLens understands.
6. `BILLING_SCOPE.md` — billing territory currently supported.
7. `RULE_GOVERNANCE.md` — how billing rules become trusted executable knowledge.
8. `BENCHMARK_PLAN.md` — how correctness will be measured.
9. `SECURITY_AND_DATA.md` — data handling and PHI boundaries.
10. `IMPLEMENTATION_STATUS.md` — what is actually built and verified.
11. `DECISIONS.md` — settled architectural/product decisions.
12. `OPEN_QUESTIONS.md` — unresolved questions that must not be silently assumed.
13. `FILE_MAP.md` — where each type of work belongs.

When documents conflict, stop and resolve the conflict in `DECISIONS.md` before implementing around it.
